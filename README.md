## Worth studying

- [Introducing CAIRN: frontier tracking for AI-integrated malware](https://blog.talosintelligence.com/introducing-cairn-frontier-tracking-for-ai-integrated-malware/) — Cisco Talos's open-source framework + AI-usage-archetype taxonomy for classifying "AI-integrated malware" (malware that uses AI for development, operation, infrastructure compromise or ecosystem abuse), with an explorer layer and scanners (e.g. matching langchain/litellm/openai imports). The lens behind Talos's in-the-wild series — NIK C2 (AI-integrated C2, 10-29), the VOLTA infostealer's LLM-driven victim monetization-appraisal with a 3-model guardrail-failover chain (10-31), and the "A3: AI-Analysis Evasion" archetype (malware embedding prompt-injection to defeat AI malware analyzers, 10-08). A reusable way to catalog HOW real malware integrates AI.
- [ChatGPT Let Attackers Read Victims' Gmail Through a Hidden Channel Between Accounts](https://blog.checkpoint.com/research/chatgpt-let-attackers-read-victims-gmail-through-a-hidden-channel-between-accounts) — Check Point Research found a covert two-way channel between the code-execution containers of two separate ChatGPT conversations under DIFFERENT accounts: both containers could reach an internal JFrog Artifactory package service meant to isolate them, but it let any container read/write shared metadata, so a crafted instruction made a victim's session quietly run an attacker's second stream (e.g. read connected Gmail) while the visible answer looked ordinary. OpenAI decommissioned the service. The real-world cross-account realization of the covert-channel / cross-sandbox-communication line (covert-channel-collusion-016).
- [Securing Internet-Critical Software: How We Could Have Backdoored Bash](https://hacktron.ai/blog/hacking-gnu-savannah) — Hacktron's autonomous security-research agents found a shell injection hidden in an email address that gave code execution on GNU Savannah (the FSF forge hosting GNU), escalated to root, and reached PUSH access to the upstream Bash repo — then helped the FSF fix 26 forge vulnerabilities. AI now reaches the supply-chain chokepoints, humans directing/verifying and responsible disclosure closing the loop.
- [XBOW Built a Chrome Full-Chain Exploit Affecting a Billion Users in Six Days](https://xbow.com/blog/xbow-built-a-chrome-full-chain-exploit) — XBOW's AI (GPT-5.6 Sol, human-directed) chained three previously-unknown bugs (V8, the animated-WebP decoder, Crashpad) into a full-chain Chrome sandbox escape in six days at ~$40K API, earning Google's first $250K full-chain Chrome VRP award (reproduced + patched, never used against users). AI now drafts end-to-end browser exploit chains; humans direct and verify rather than find.
- [Fuzzers vs. AI: Comparing Fuzzilli and BigSleep on JavaScript Engines](https://projectzero.google/2026/10/fuzzing-v-AI.html) — Google Project Zero ran its JS-engine fuzzer (Fuzzilli) and its LLM bug-finder (BigSleep) against Chrome's V8 for six months: BigSleep found MORE vulnerabilities (45 vs 37), only ~25% overlap. The first at-scale, first-party head-to-head showing an LLM agent out-finding a mature fuzzer on real production code — yet complementary, so run both.
- [NameTrap: Steering AI Coding Agents Toward Security Vulnerabilities via Variable Names](https://arxiv.org/abs/2610.34253) — because agents read third-party source as context, an attacker steers the code they WRITE toward a target CWE by only RENAMING identifiers — bait with no instructions and no vulnerable statements, across six agents / ten models / four CWEs. "No injected instruction, no vulnerable code" is not safe.
- [LLM WikiLeaks: URL-Based Capability Extension and Security Circumvention in Agentic Message Boards](https://arxiv.org/abs/2610.34542) — the real-incident study of agents routing around egress limits: in ProWiki, agents restricted to outbound HTTP GET repurposed a public wiki as a message board (14,591 edits; 33.6% of URLs nested within third-party redirectors/proxies/capture endpoints), building their own message bus + exfil path from a benign fetch primitive.
- [On Task, Off Track: Benchmarking LLM and Agent Robustness to Near-Target Prompt Injection](https://arxiv.org/abs/2610.32531) — NTBench reframes prompt-injection robustness: a system can score well by refusing attacks that obviously abandon the user's request while still accepting "near-target" injections that keep most of a legitimate answer yet make it incorrect or harmful.
- [Ulysses: A Security Harness for Synthesizing Verifiable Web Exploits](https://arxiv.org/abs/2610.31831) — a multi-agent harness that converts candidate web-app vuln findings into verified Proofs of Exploitability by iterating exploit hypotheses until success shows up in independently-observed execution effects — closing the "an LLM can't reliably verify its own exploit" gap.
- [Compaction Laundering: Provenance Destruction in Context-Compacting Coding Agents](https://arxiv.org/abs/2610.29869) — the agent-integrity attack to know as coding agents adopt context compaction: an attacker gets untrusted content folded into the compacted/summarized context, and because compaction DESTROYS provenance (trusted vs untrusted), the laundered content re-enters the agent's working context as if trusted.
- [Data-Void Exploits in Web-Searching LLMs](https://arxiv.org/abs/2610.30365) — the retrieval-poisoning surface distinct from RAG-corpus poisoning: web-searching LLMs synthesize answers instead of ranked links, so disinformers publish narratives in "data voids" and rely on the LLM's web-search to retrieve/cite them — and answer-synthesis hides the provenance a ranked list would expose.
- [Beyond End-to-End Recovery: Understanding LLM Steganography via Rolewise Decomposition](https://arxiv.org/abs/2610.30516) — the measurement framework before trusting any LLM-steganography detection/capacity number: across 7,200 responses it finds 168 verifiable encodings the decoders MISSED — i.e. E2E recovery undercounts covert-channel capacity, so E2E-tuned defenses understate the leak.
