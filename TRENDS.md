  - 2026-07-06 — https://arxiv.org/abs/2607.06595 — "GhostWriter" (When Agents Remember Too Much): a memory-poisoning attack against tool-using PERSONAL LLM agents (email/calendar/repo assistants at the convergence of conversational + action-planning agents) — a two-phase attack (injection: an adversary sends a hidden payload to the agent; activation: the poisoned memory is later retrieved) that exploits the absence of security-focused memory governance, reaching ~98% injection and ~60% activation against state-of-the-art agents; ships the AM-Sentry defense (memory-saving policy + memory-retrieval screen).   - 2026-07-07 — https://arxiv.org/abs/2607.05744 — "Unicode TAG-Block Concealment of Tool-Metadata Payloads in the Model Context Protocol": isolates a NEW structural MCP attack — a "concealment encoding" / approval-view fidelity gap. MCP renders a tool's name/description/schema ONCE in a one-time approval dialog, then injects it verbatim into the model's context every subsequent turn; nothing in the protocol requires the rendered approval view and the bytes delivered to the model to match. Unicode's TAG block (U+E0000–U+E007F) has no assigned glyph in any mainstream terminal, chat or IDE renderer, so a payload written in it is ABSENT from what a human reviewer approves yet survives byte-for-byte into the model's tokenizer — demonstrated across three INDEPENDENT MCP server implementations. Distinct from ShareLock (multi-tool dispersal) and SkillCloak (payload transformation): the exploit lives in the human↔model rendering gap of the approval UX, not the tool logic.
